# Action1 Insights

Interactive, read-only asset and vulnerability reporting using the registered Action1 MCP gateway. The existing layout, search, charts, risk filters, asset details, pagination, CSV import and protected CSV export are retained.

From the repository root, run `npm run dashboard`, then open `http://127.0.0.1:8765`. Node.js 22+, the existing dependencies, the `codex` CLI and the existing `action1` registration are required. Unlock or authorize 1Password if prompted. `node dashboard/preview.mjs` remains an equivalent launch command. Set `ACTION1_DASHBOARD_PORT` to choose a different port with the main launch command, or `ACTION1_CODEX_COMMAND` if Codex is not on PATH.

The local server launches the saved `action1` command through the MCP SDK, so 1Password injects current credentials into the gateway subprocess. It requires the confirmed NA-2 configuration. It only exposes organization discovery and asset inventory reads; the browser never receives API credentials. The registered organization allowlist and API credential permissions continue to apply. Select an organization before asset reads; a single accessible organization is selected automatically. Refresh retrieves current data. Restart the local server after changing credentials or registration.

Asset reads are bounded to five 100-record pages per request. Partial results are labeled and offer **Load more from Action1** using the gateway continuation offset. Metrics and CSV exports represent loaded records; partial exports include `partial` in their filename. Pagination is over changing live data, not a fixed audit snapshot. Unknown patch and vulnerability counts remain unknown. Both the live nested summaries (`missing_updates.critical/other`, `vulnerabilities.critical/other`) and the original flat CSV columns are supported. Last-seen timestamps retain the source representation and unverified timezone. Findings are endpoint aggregates, not unique CVEs. Duplicate names remain separate IDs.

Failed refreshes display an error and label retained data as potentially stale. Changing organization clears the previous organization's records. CSV imports use the original 18-column schema, remain in browser memory and are never uploaded. Refresh returns to Action1. The old `dist/data.js` snapshot is excluded from Git, is never requested, and is not served by the local server.

The bridge listens only on `127.0.0.1`, checks Host and Origin, requires a per-launch session header for API reads, disables caching, and only serves an explicit static-file allowlist. No tenant records are written to disk. The retained `.openai/hosting.json` identifies the previous static Site; this local Node/stdio bridge cannot run on static Sites hosting. The hosted snapshot has not been replaced with a live connection. Remote hosting would require a separate authenticated, caller-scoped service.

Validation: `npm test` runs gateway and dashboard regression checks. `node dashboard/verify.mjs` runs dashboard checks. `node dashboard/live-check.mjs` starts a fresh registered gateway, prints only counts and field shapes, and samples ten assets only when there is a single complete organization scope. For multiple organizations, set `ACTION1_DASHBOARD_CHECK_ORGANIZATION` to a discovered, explicitly selected ID. Skipped asset checks are not successful validation.
